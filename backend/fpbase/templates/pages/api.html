FPbase REST API

FPbase supports a REST API to search and retrieve protein attributes in JSON or CSV format. This is still a work in development and is subject to change. This page details how to use the current API.

Basics

A simple way to learn about the API is to build a search using the advanced search query builder, and look at the resulting parameters in the URL. Any URL generated with the query builder can be directly used in the API, simply be replacing /search/ in the URL with /api/proteins/. For instance, a query built on the advanced search builder with the following filters:

Name contains green
Quantum Yield is greater than or equal to 0.7

would generate the following url:
https://www.fpbase.org/search/?name__icontains=green&default_state__qy__gte=0.7

By replacing /search/ in the URL with /api/proteins/:
https://www.fpbase.org/api/proteins/?name__icontains=green&default_state__qy__gte=0.7

you will now be searching using the protein api. Scripts receive JSON by default, while a web browser is shown an HTML page. To choose the format explicitly, add &format=json (or format=csv) to the URL:
https://www.fpbase.org/api/proteins/?name__icontains=green&default_state__qy__gte=0.7&format=json

The GraphQL API, with an interactive explorer. It covers proteins, dyes, spectra, filters, cameras, light sources, microscopes and references, and lets you ask for exactly the fields you need. The fpbase Python package wraps it.

Choosing fields and paging

fields=name,slug,states__ex_max
Only these fields (nested ones with __). Smaller responses are faster to fetch and to parse.
include_fields=states__ex_spectrum
Add on-demand fields to the full output. The spectra, states__ex_spectrum and states__em_spectrum (as [[wavelength, value], ...]), are left out unless named here or in fields.
limit=50&offset=100
Page through a list. Without limit (or page) the whole list is returned. page=3&page_size=50 means the same as this example (page_size defaults to 100).

Searchable Fields

The following field name and lookups can be used. Fieldnames and lookups must be separated by a double-underscore "__". For example: name__icontains. The exact lookup is the exception: use the bare field name, for example agg=m. As a shortcut, name=mCherry is the same as name__iexact=mCherry. See below for an explanation of each lookup operator.

Unrecognized query parameters return a 400 error listing the valid ones (rather than being ignored).

The default_state__ prefix on the fluorescence fields below may be dropped: ex_max__gte=600 is the same as default_state__ex_max__gte=600. Likewise pdb=2H5Q finds a protein by PDB ID and search=cherry matches names and aliases.

default_state__ ?

You will notice that many of the fields describing fluorescence attributes (ex/em max, qy, ext_coeff) must be preceeded by default_state__. This is because some proteins can have multiple states. Currently, the API only searches the default state for a given protein (but it still must be specified in the query).
